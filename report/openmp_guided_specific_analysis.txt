=== OpenMP Guided Scheduling Performance Analysis ===
Date: June 30, 2025
Configurations Tested: 40 (5 problem sizes × 8 thread counts)
Methodology: Best of 3 runs per configuration

==================================================
EXECUTIVE SUMMARY
==================================================

Guided scheduling demonstrates excellent performance characteristics, showing:
- Competitive performance with dynamic scheduling 
- Better consistency across thread counts
- Strong efficiency at moderate thread counts (24-32)
- Optimal performance typically at 32 threads

==================================================
THREAD COUNT OPTIMIZATION ANALYSIS
==================================================

Optimal Thread Count Distribution:
- 24 threads: 2 configurations (40%)
- 32 threads: 2 configurations (40%)
- 64 threads: 1 configuration (20%)

Thread Performance Characteristics:
- 1-8 threads: Linear scaling (>86% efficiency)
- 16 threads: Good performance (63% efficiency)
- 24-32 threads: Optimal performance zone
- 64 threads: Peak performance but lower efficiency

==================================================
PROBLEM SIZE SCALING ANALYSIS
==================================================

Small Problems (1000×1000):
- Low iterations (1000): 32 threads optimal, 11.86× speedup
- Medium iterations (3000): 24 threads optimal, 13.38× speedup  
- High iterations (5000): 24 threads optimal, 13.67× speedup
- Trend: Lower thread counts better for higher iterations

Medium Problems (2000×2000):
- 1000 iterations: 32 threads optimal, 11.92× speedup
- Shows good scaling potential

Large Problems (3000×3000):
- 1000 iterations: 64 threads optimal, 11.78× speedup
- Memory bandwidth becomes limiting factor

==================================================
EFFICIENCY ANALYSIS
==================================================

High Efficiency Zones (>50%):
- 1000×1000, 3000 iter @ 24 threads: 55.8%
- 1000×1000, 5000 iter @ 24 threads: 57.0%
- All configurations @ 1-8 threads: >86%

Moderate Efficiency (30-50%):
- Most optimal configurations: 37-40%
- Good balance of performance and resource usage

Low Efficiency (<30%):
- High thread counts (64) with small problems
- Resource contention and overhead dominant

==================================================
GUIDED SCHEDULING CHARACTERISTICS
==================================================

Adaptive Load Balancing:
- Starts with large chunks for efficiency
- Reduces chunk size as work progresses
- Better than static for irregular workloads
- Lower overhead than pure dynamic

Performance Stability:
- Consistent results across runs (±1-2%)
- Less variance than dynamic scheduling
- Predictable performance characteristics

Thread Utilization:
- Good scaling up to 32 threads
- Diminishing returns beyond 32 threads
- Better resource efficiency than static

==================================================
PERFORMANCE RECOMMENDATIONS
==================================================

For Maximum Performance:
- Use 32 threads for most configurations
- 24 threads for high-iteration small problems
- 64 threads only for very large problems

For Balanced Performance/Efficiency:
- Use 16-24 threads (63-57% efficiency)
- Good performance with reasonable resource usage
- Suitable for shared environments

For High Efficiency:
- Use 4-8 threads (>86% efficiency)
- Near-linear scaling
- Minimal resource overhead

==================================================
CONCLUSIONS
==================================================

1. Guided scheduling provides excellent performance with good predictability
2. Optimal thread count is typically 24-32 for most configurations  
3. Higher iteration counts improve parallel efficiency significantly
4. Memory bandwidth becomes the limiting factor for large problems
5. Guided scheduling offers a good balance between performance and overhead
6. Thread efficiency remains reasonable up to 32 threads

Guided scheduling emerges as a robust choice that combines the predictability
of static scheduling with improved load balancing, making it suitable for
production workloads requiring consistent performance.
